## Licensing position

Project source code is licensed under Apache-2.0. Non-code assets are deliberately separated so public source visibility does not silently turn every `.blend`, `.glb`, texture, render, or audio file into an Apache-licensed asset.

See:

- `LICENSE`
- `ASSET_LICENSE.md`
- `THIRD_PARTY_NOTICES.md`
- `docs/art/MPFB_ASSET_LICENSE_EVIDENCE.md`

## Provenance findings

### MakeHuman / MPFB

The existing project evidence records MPFB/MakeHuman core graphical assets under CC0 and separately records the add-on/program license. It also records that no third-party contributed MakeHuman assets were installed or referenced for the accepted character pipeline. The upstream license texts are retained under `third-party-notices/mpfb/`.

### Google Gemini-generated BGM

The six committed BGM tracks were generated by the project owner using Google Gemini. Google states in its current general Terms that it does not claim ownership over original content generated by services that support generation, while users remain responsible for third-party rights and applicable law. These tracks are documented in `THIRD_PARTY_NOTICES.md` and are not included in the Apache-2.0 software grant.

## Repository hygiene policy

Keep production source, runtime assets, tests, and curated acceptance evidence. Do not commit transient deformation dumps, CI output, temporary screenshots, local Blender/MCP state, repeated WIP captures, generated project-tree snapshots, or ad-hoc patch dumps. Large editable source media follows `.gitattributes` Git LFS rules.

The public-readiness branch removes large tracked intermediate evidence from the current tree without rewriting historical commits.

## History and privacy decision

History rewriting is intentionally avoided by default because this project's existing PR/maintenance history is useful evidence of sustained open-source maintenance. A rewrite should occur only if a real secret is discovered or the owner decides that historical commit-email exposure is unacceptable.

Before the final visibility switch, the remaining mandatory decision is therefore:

1. run/confirm a full-history secret scanner with access to the Git repository; and
2. explicitly accept the historical author-email exposure or perform a dedicated email rewrite.

## GitHub integration limitation

The connected GitHub App can modify repository files and pull requests but currently receives HTTP 403 for the Secret Scanning Alerts and Branch Protection APIs. Those account/repository settings cannot be truthfully marked complete from this integration alone and must be verified through an authorized GitHub settings surface before publication.
